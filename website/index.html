What Amon is for

Use the public web without turning everything into a permanent system of record.

The goal is not to hide the web behind marketing language. The goal is to give you a better default posture: search when you need breadth, switch into cleaner reading when you need focus, use a protected session when a task requires the original site, and save only the material you intentionally want in your workspace.

Search / Browse

Start broad, without building a long-term archive of every step.

Amon’s backend direction is to handle search and retrieval transiently. It exists to help you reach public information, not to become the main place your browsing history accumulates.

Clean View

Read the substance instead of the page furniture.

When a page is worth keeping attention on, Amon aims to present a quieter reading mode that preserves the material you need and cuts the noise you do not.

Protected Session

Go to the real site when the task actually needs it.

Some public-web tasks need forms, account flows, or interactive pages. Protected Session is the mode for those selected cases: more direct access, more control, and tighter boundaries than an always-on browser posture.

Workspace

Keep the work product local unless you choose otherwise.

The current product direction centers on a local workspace for saved sources, excerpts, and notes. That keeps the “what I decided to keep” boundary separate from the transient work of browsing.

Private by default. Deeper when needed.

That is the operating idea behind the product. Amon should help you move from search to reading to action without pretending every task needs the same exposure, persistence, or trust tradeoff.

Honest scope

Designed for public-web work, not as a blanket claim about everything.

The v1 direction is focused and specific: public-web search, retrieval, cleaner reading, protected sessions for selected tasks, and local workspace storage. That is intentionally narrower than “privacy for everything.”

Service role Search and retrieval support, not broad content warehousing.

Privacy posture

What we can say plainly today

  • The service direction is to minimize durable storage of query text, result sets, and page content.
  • Saved material is meant to live in the local workspace rather than a default cloud archive.
  • Protected Session is for selected tasks that genuinely need the original public website.
  • Amon still has infrastructure, authentication, and operational boundaries, so the site should be explicit about those realities.
What we do not claim

No privacy theater

  • No claim that every web task is anonymous or invisible.
  • No claim that public websites stop seeing you once you choose to visit them directly.
  • No claim that every future mode already exists in polished production form.
  • No claim that internal ops or admin surfaces belong anywhere near the public site.
