About / Vision

Built around a simple discomfort.

Working with the public web often means switching between noisy pages, permanent browser history, fragmented notes, and unclear privacy tradeoffs. Amon exists to make that workflow calmer and more deliberate.

Vision

The web is useful. The default posture around it usually is not.

Amon is oriented around public-web work that should feel cleaner, more understandable, and more intentional. That means separating browsing from saving, separating direct-site tasks from quiet reading, and separating public messaging from internal product surfaces.

Why this site

A public front door that matches the real architecture.

The public site should explain the product and trust posture, invite the right people in, and remain visibly separate from internal ops, internal product tooling, backend control planes, and app-specific implementation details.

The public website should say what Amon is, not leak how internal surfaces are wired.

That is why this implementation lives in its own dedicated site folder and uses only static public content.

Amon. A public front door, kept separate on purpose.
